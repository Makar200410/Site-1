# Техническое задание: сайт для подготовки к ОГЭ по химии

**Версия:** 1.0
**Дата:** 29.08.2026
**Тип проекта:** бесплатный образовательный ресурс
**Исполнитель:** разработка своими силами (один человек)

---

## 1. Цели и рамки проекта

### 1.1. Цель
Создать бесплатный сайт для самостоятельной подготовки девятиклассников к ОГЭ по химии, который приводит пользователей из органического поиска и позволяет: изучить теорию, отработать каждое задание экзамена на тренажёре, пройти пробник на время и отслеживать свой прогресс.

### 1.2. Бизнес-модель
Монетизации нет. Ключевая метрика успеха — **органический трафик из Яндекса и Google** и глубина вовлечения (доля пользователей, решивших ≥ 10 заданий).

Из этого следует главный технический приоритет: **SEO и скорость важнее богатства функционала**. Любое решение, ухудшающее индексируемость или скорость загрузки, отклоняется.

### 1.3. Что НЕ входит в проект
Явно выносится за рамки, чтобы не размывать фокус:

- Регистрация, авторизация, аккаунты, вход через соцсети
- Сбор персональных данных в любом виде
- Приём платежей, подписки, реклама
- Видеоуроки и вебинары
- Форум, комментарии, чат, любой UGC
- Проверка развёрнутых ответов человеком или нейросетью
- Мобильные приложения

## 2. Целевая аудитория

| Сегмент | Доля | Устройство | Что нужно |
|---|---|---|---|
| Ученики 9 класса | ~85% | Смартфон (Android, средний ценовой сегмент) | Быстро найти разбор конкретного задания, потренироваться |

- Расчёт на медленный мобильный интернет и слабые устройства.
- Трафик пиковый: сентябрь–май, взрывной рост в апреле–мае.
- Типичная сессия — короткая и по конкретному запросу («задание 8 ОГЭ химия»), а не «зашёл почитать».

## 3. Структура экзамена (предметная модель)

Основа контентной модели. Актуальные параметры:

- **24 задания**: 19 с кратким ответом (часть 1) + 5 с развёрнутым (часть 2)
- **40 первичных баллов** максимум
- **180 минут** на выполнение
- Задание 24 — реальный химический эксперимент
- Шкала перевода: 0–9 → «2», 10–20 → «3», 21–30 → «4», 31–40 → «5»

> ⚠️ **Обязательное требование:** структура экзамена меняется. Все эти параметры (число заданий, баллы, шкала, время) выносятся в **один конфигурационный файл** `src/config/exam.ts` и нигде не хардкодятся. Перед каждым учебным годом сверять с демоверсией и кодификатором ФИПИ и править только конфиг.

## 4. Технический стек и обоснование

### 4.1. Выбор
| Слой | Решение |
|---|---|
| Фреймворк | **Astro 5** |
| Интерактивные блоки | **React**-острова (`client:visible` / `client:load`) |
| Язык | **TypeScript** (строгий режим) |
| Стили | **Tailwind CSS** |
| Контент | **Content Collections**: MDX для теории, JSON/YAML для заданий |
| Валидация контента | **Zod**-схемы (встроены в Content Collections) |
| Химические формулы | **KaTeX + расширение mhchem**, рендер на этапе сборки |
| Поиск по сайту | **Pagefind** (статический индекс, без бэкенда) |
| Хранение прогресса | **localStorage** браузера |
| Аналитика | **Яндекс.Метрика** |
| Бэкенд | **отсутствует** |

### 4.2. Почему Astro, а не Next.js или чистый React

Ты сформулировал требование как «оптимизированность, семантика и SEO» — стек подобран строго под это.

- **Ноль JavaScript по умолчанию.** Astro отдаёт чистый HTML. Страницы теории — самая ценная для SEO часть сайта — грузятся без единого килобайта JS. Это даёт почти идеальные Core Web Vitals, которые Google учитывает в ранжировании. React SPA здесь проигрывает принципиально: контент собирается на клиенте, робот получает пустой `<div>`.
- **Острова гидратации.** JS подключается точечно и только там, где он реально нужен: тренажёр, таймер пробника, справочные таблицы. Статья про периодический закон не тянет за собой рантайм React.
- **Content Collections + Zod.** Задания и теория лежат в файлах, а их структура проверяется типами при сборке. Если ты забудешь поле `answer` у задания — сборка упадёт с понятной ошибкой, а не сайт сломается у пользователя. Для одиночного разработчика, который сам пишет сотни единиц контента, это критично.
- **Порог входа ниже, чем у Next.js.** Нет App Router, серверных компонентов, кэширования и прочей сложности, которая тебе не понадобится на статическом сайте.
- **Сборка в статику** → бесплатный или почти бесплатный хостинг, невозможность «положить» сайт нагрузкой, отсутствие серверных уязвимостей.

**Компромисс, который принимается осознанно:** статическая сборка означает, что после добавления заданий нужно пересобрать и залить сайт. Решается автоматизацией через CI (см. п. 11).

### 4.3. Почему контент в файлах репозитория, а не в CMS

Ты оставил этот выбор за мной. Решение: **MDX и JSON в git-репозитории**, без CMS.

- Отдельная CMS (Strapi) требует своего сервера, базы, обновлений безопасности — это второй проект внутри первого, при том что редактор у сайта ровно один человек.
- Git даёт бесплатно: историю всех правок, откат к любой версии, резервную копию контента и возможность править материалы с любого устройства через веб-интерфейс GitHub.
- Zod-схема заменяет админку в главном: не даёт создать сломанное задание.
- Самописная админка — это +2–3 недели работы и постоянная поддержка ради задачи, которую решает текстовый редактор.

**Когда пересмотреть:** если появятся сторонние авторы, не умеющие работать с git. Тогда поверх файлов ставится Decap CMS или Keystatic — они дают визуальный редактор, оставляя контент в репозитории.

## 5. Контентная модель

### 5.1. Задание (`src/content/tasks/*.json`)

```typescript
{
  id: string;                    // "08-014" — номер задания ОГЭ + порядковый
  examNumber: number;            // 1..24 — номер в структуре экзамена
  topicId: string;               // ссылка на раздел кодификатора
  difficulty: "base" | "advanced" | "high";
  answerType: "single" | "multiple" | "matching" | "numeric" | "sequence" | "extended";
  statement: string;             // условие, MDX с поддержкой mhchem
  options?: Option[];            // варианты для выбора
  correctAnswer: string | string[] | number;
  tolerance?: number;            // допуск для числового ответа, напр. 0.01
  maxScore: number;              // 1..5
  solution: string;              // полный разбор, MDX
  hint?: string;                 // подсказка до показа решения
  criteria?: string[];           // критерии оценивания для развёрнутых
  theoryRefs: string[];          // id статей теории
  tags: string[];
  source?: string;               // происхождение задания
}
```

### 5.2. Типы ответов и способ проверки

| Тип | Пример задания | Проверка |
|---|---|---|
| `single` | Выбор одного варианта из четырёх | Автоматически |
| `multiple` | «Выберите два верных утверждения» | Автоматически, множество без учёта порядка |
| `matching` | Установить соответствие | Автоматически, построчно |
| `numeric` | Вычислить массовую долю | Автоматически, с допуском `tolerance` |
| `sequence` | Расположить в порядке возрастания | Автоматически, с учётом порядка |
| `extended` | Задания 20–24 | **Самопроверка** |

**Про развёрнутые ответы.** Автоматически проверить их без бэкенда и нейросети невозможно. Честное решение: пользователь пишет ответ в поле, затем открывает эталонное решение и критерии оценивания и **сам выставляет себе баллы** по чек-листу. Это не костыль — умение читать критерии само по себе полезный навык перед экзаменом. Ученик должен видеть предупреждение, что балл он ставит себе сам.

### 5.3. Статья теории (`src/content/theory/*.mdx`)

```typescript
{
  title: string;
  description: string;           // 150–160 символов, идёт в meta description
  topicId: string;
  order: number;
  relatedTasks: number[];        // номера заданий ОГЭ, где тема встречается
  updatedAt: Date;
  readingTime: number;
}
```

### 5.4. Химические обозначения

Формулы и уравнения записываются через синтаксис mhchem: `$\ce{H2SO4}$`, `$\ce{2H2 + O2 -> 2H2O}$`.

**Требование:** KaTeX подключается как плагин Markdown и рендерится **на этапе сборки** в статический HTML+CSS. На клиент не уходит ни библиотека, ни скрипт. Это принципиально: MathJax в браузере съел бы весь выигрыш в скорости.

Простые индексы в заголовках и мета-тегах пишутся юникодом (H₂O), чтобы корректно отображаться в поисковой выдаче.

## 6. Структура сайта и URL

```
/                                — главная
/teoriya/                        — оглавление теории
/teoriya/[topic]/                — раздел (напр. /teoriya/stroenie-atoma/)
/teoriya/[topic]/[article]/      — статья
/zadaniya/                       — все 24 задания списком
/zadaniya/[n]/                   — разбор задания № n: что проверяет,
                                   алгоритм решения, типовые ошибки, примеры
/trenazher/                      — настройка тренировки
/trenazher/sessiya/              — сама тренировка (noindex)
/probniki/                       — список пробных вариантов
/probniki/[id]/                  — прохождение варианта (noindex)
/spravochnik/                    — справочные таблицы
/spravochnik/tablitsa-mendeleeva/
/spravochnik/rastvorimost/
/spravochnik/ryad-aktivnosti-metallov/
/moy-progress/                   — личный прогресс (noindex)
/o-proekte/
```

**Правила URL:**
- Только строчные латинские буквы, транслитерация, дефисы
- Обязательный завершающий слеш, единообразно на всём сайте
- Никаких GET-параметров в индексируемых адресах
- Структура фиксируется сразу: менять URL после индексации дорого

**Страницы `/zadaniya/[n]/` — главный SEO-актив.** Запросы вида «задание 15 ОГЭ химия» частотны и конкретны. Каждая такая страница обязана содержать: описание проверяемых умений, разбор алгоритма, 3–5 примеров с решениями, ссылки на теорию и кнопку «тренировать это задание».

## 7. Функциональные требования

### 7.1. Модуль «Теория»
- Иерархия: раздел → статья, соответствует кодификатору ФИПИ
- Оглавление статьи с якорями, липкое на десктопе
- Блоки: определение, важно, типичная ошибка, пример — визуально различимые
- В конце каждой статьи: «Проверь себя» — 3–5 заданий по теме
- Кросс-ссылки на связанные статьи и на номера заданий ОГЭ
- Индикатор прочитанности (из localStorage)

### 7.2. Модуль «Тренажёр»

**Настройка сессии:**
- По номеру задания ОГЭ (1–24)
- По теме кодификатора
- По уровню сложности
- Режим «только ошибки» — задания, где пользователь ошибался
- Режим «не решённые ранее»
- Количество: 5 / 10 / 20 / все

**Прохождение:**
- Одно задание на экран
- Проверка ответа по кнопке, мгновенный отклик без перезагрузки
- После ответа: вердикт, правильный ответ, полный разбор, ссылка на теорию
- Кнопка «Подсказка» до ответа, если у задания заполнено поле `hint`
- Доступ к справочным таблицам не выходя из задания
- Прогресс-бар сессии
- Возможность прервать сессию с сохранением результата

**Итоги сессии:** число верных, время, разбивка по темам, список ошибок с быстрым переходом к теории.

### 7.3. Модуль «Пробники»
- Полный вариант: 24 задания в порядке экзамена
- **Таймер 180 минут**, обратный отсчёт, предупреждения за 30 и 5 минут
- Навигация по номерам заданий с отметкой отвеченных
- Возможность отметить задание флажком «вернуться»
- Свернуть/развернуть справочные таблицы (как на реальном экзамене)
- Автосохранение ответов в localStorage каждые 15 секунд — при закрытии вкладки прогресс не теряется
- По завершении: автопроверка части 1, самопроверка части 2 по критериям
- Итог: первичный балл, оценка по пятибалльной шкале, разбор каждого задания

### 7.4. Модуль «Прогресс»

Без регистрации, всё в localStorage.

**Схема хранения:**
```typescript
{
  version: 1,                              // для будущих миграций
  tasks: { [taskId]: { attempts, correct, lastAt } },
  theory: { [articleId]: { read: true, at } },
  mocks: [ { id, date, score, grade, answers } ],
  streak: { current, longest, lastActiveDate }
}
```

**Отображение:** процент решённых по каждому из 24 заданий, слабые темы (точность < 60%), история пробников с графиком динамики, серия дней подряд.

**Обязательные требования из-за отсутствия аккаунта:**
- Честное предупреждение при первом сохранении: прогресс хранится в этом браузере и пропадёт при очистке данных или смене устройства
- **Экспорт прогресса в JSON-файл** и импорт обратно — это единственный способ перенести данные на другое устройство, поэтому кнопки должны быть заметными
- Поле `version` в схеме обязательно: без него любое изменение структуры сломает данные существующих пользователей
- Кнопка полного сброса

### 7.5. Модуль «Справочник»
Материалы, разрешённые на экзамене:
- Периодическая таблица — интерактивная, тап по элементу открывает карточку
- Таблица растворимости — с подсветкой пересечения строки и столбца
- Электрохимический ряд напряжений металлов
- Формулы для расчётных задач с пояснениями

Доступны как отдельные страницы (SEO-трафик: «таблица растворимости» ищут постоянно) и как всплывающая панель внутри тренажёра и пробника.

## 8. Требования к SEO

Раздел приоритетный: это основной канал привлечения.

### 8.1. Семантическая вёрстка
- Один `<h1>` на страницу, иерархия `h2`–`h4` без пропусков уровней
- Теги `<article>`, `<section>`, `<nav>`, `<aside>`, `<main>`, `<time>` по назначению
- Списки размечаются `<ul>`/`<ol>`, а не `<div>` с точками
- Все изображения с осмысленным `alt`
- Хлебные крошки на каждой внутренней странице

### 8.2. Микроразметка Schema.org (JSON-LD)
- `BreadcrumbList` — на всех внутренних страницах
- `Article` — на статьях теории, с `datePublished` и `dateModified`
- `FAQPage` — на страницах заданий, где есть блок частых вопросов
- `EducationalOccupationalProgram` или `LearningResource` — на разделах
- `WebSite` с `SearchAction` — на главной

### 8.3. Мета-теги
- Уникальные `title` и `description` для каждой страницы, без шаблонной генерации по маске
- Длина `title` до 60 символов, `description` — 150–160
- `canonical` на каждой странице
- Open Graph и Twitter Card; **OG-изображения генерируются на этапе сборки** (Satori/`astro-og-canvas`) — свои для каждой страницы
- `robots: noindex` на служебных страницах: сессия тренажёра, прохождение пробника, личный прогресс

### 8.4. Техническое
- `sitemap.xml` — генерируется автоматически (`@astrojs/sitemap`)
- `robots.txt` с указанием на карту сайта
- Одно зеркало: HTTPS, без `www` (или с — но строго одно, остальное 301-редиректом)
- Никаких дублей: одна страница — один адрес
- Подключение к **Яндекс.Вебмастеру** и **Google Search Console** до публикации контента

### 8.5. Семантическое ядро
Ставка на низкочастотные конкретные запросы — конкурировать с крупными агрегаторами по «ОГЭ химия» бессмысленно.

Кластеры:
1. `задание N ОГЭ химия` + «как решать», «разбор», «теория» — 24 страницы
2. Темы кодификатора: «степень окисления», «ионные уравнения», «массовая доля вещества»
3. Задачные: «как найти массовую долю элемента», «как расставить коэффициенты в ОВР»
4. Справочные: «таблица растворимости», «ряд активности металлов»
5. Организационные: «сколько заданий в ОГЭ по химии», «сколько баллов на 4»

**Перелинковка:** теория ↔ задания ↔ тренажёр. Из каждой статьи — ссылки минимум на 3 связанных материала. Это и SEO, и глубина просмотра.

### 8.6. Целевые показатели скорости
| Метрика | Порог |
|---|---|
| LCP | < 2.0 с (4G) |
| CLS | < 0.05 |
| INP | < 200 мс |
| Lighthouse Performance (mobile) | ≥ 95 |
| Lighthouse SEO / Accessibility | 100 / ≥ 95 |
| JS на странице теории | 0 КБ |
| Вес страницы теории | < 150 КБ |

**Технические меры:** шрифты только `woff2` с `font-display: swap` и `preload`, изображения в WebP/AVIF через `<Image />` Astro с явными размерами, критический CSS инлайном, никаких сторонних скриптов кроме Метрики (грузится отложенно).

## 9. Требования к дизайну и UX

- **Mobile-first.** Все макеты сначала под 360 px.
- Основной текст ≥ 16 px, межстрочный интервал ≥ 1.6
- Область нажатия любого интерактивного элемента ≥ 44×44 px
- Контрастность по WCAG AA (4.5:1)
- Тёмная тема с сохранением выбора и учётом `prefers-color-scheme`
- Полная навигация с клавиатуры, видимый фокус
- Формулы не должны ломать вёрстку на узких экранах: длинные уравнения — с горизонтальной прокруткой внутри своего блока
- Стилистика — спокойная и «взрослая»: девятиклассники отторгают инфантильное оформление
- Никаких модальных окон, перекрывающих контент при входе

## 10. Хостинг, домен, инфраструктура

**Бюджет 500–2000 ₽/мес выбранной архитектурой перекрывается с запасом** — статический сайт почти ничего не стоит.

| Статья | Стоимость |
|---|---|
| Домен `.ru` | 200–400 ₽/год |
| Хостинг статики | 0–300 ₽/мес |
| SSL | 0 ₽ (Let's Encrypt) |

**Варианты хостинга:**
1. **Российский хостинг** (Timeweb, Beget, Selectel) — предпочтительный. Гарантированная доступность для российской аудитории, быстрый отклик, привычная поддержка. Для статики хватит самого дешёвого тарифа.
2. **Зарубежные платформы** (Vercel, Netlify, Cloudflare Pages) — бесплатны и удобны, но доступность для пользователей из России нужно проверить на текущий момент: были случаи замедления и блокировок. Проверь перед выбором.

Рекомендация: **российский хостинг + CDN**. Терять трафик из-за инфраструктурных проблем на бесплатном ресурсе бессмысленно.

**Домен:** короткий, читаемый, желательно с ключевым словом. Проверить, что не был под фильтрами (`https://web.archive.org` + сервисы проверки истории домена).

## 11. Процесс разработки

- **Git + GitHub**, ветки `main` (прод) и `dev`
- **CI/CD**: push в `main` → автосборка → деплой. Добавление задания = коммит файла, дальше всё само
- **Проверки в CI**: TypeScript, ESLint, валидация Zod-схем контента, Lighthouse CI с порогами из п. 8.6 — сборка падает при регрессе скорости
- Резервная копия: сам репозиторий + периодический экспорт в отдельное хранилище

## 12. Этапы и сроки

Оценка из расчёта «несколько часов в день».

### Этап 0. Подготовка (1 неделя)
Кодификатор и структура тем, схемы контента, макеты 5 ключевых экранов, домен, репозиторий, каркас проекта.
**Готово, когда:** собирается пустой сайт с рабочим деплоем.

### Этап 1. MVP — контентное ядро (4–5 недель)
Главная, теория (первые 15 статей), 24 страницы разбора заданий, справочник, базовый тренажёр без фильтров, 100+ заданий, полная SEO-обвязка.
**Готово, когда:** сайт добавлен в Вебмастер, Lighthouse ≥ 95, первые страницы в индексе.

### Этап 2. Тренажёр и прогресс (3 недели)
Фильтры сессии, режимы «ошибки» и «нерешённые», localStorage, страница прогресса, экспорт/импорт.
**Готово, когда:** прогресс переживает перезагрузку и переносится файлом на другое устройство.

### Этап 3. Пробники (2–3 недели)
Полные варианты, таймер, автосохранение, самопроверка части 2, подсчёт балла и оценки.
**Готово, когда:** вариант проходится целиком на телефоне без потери данных.

### Этап 4. Контент (постоянно)
Наполнение до 400–500 заданий и полного покрытия кодификатора теорией.

**Итого до полнофункционального сайта: ~3 месяца.** Контент продолжает наполняться дальше.

## 14. Риски

| Риск | Вероятность | Что делать |
|---|---|---|
| **Контент не пишется** — 500 качественных заданий с разборами это сотни часов | Высокая | Главный риск проекта. Код — 20% работы, контент — 80%. Ввести норму (например, 5 заданий в день) и вести счётчик. Запускаться с 100 заданиями, не ждать полноты |
| Изменение структуры ОГЭ | Средняя | Все параметры в одном конфиге; ежегодная сверка с демоверсией ФИПИ |
| Потеря прогресса у пользователей | Средняя | Заметный экспорт, честное предупреждение, поле `version` в схеме |
| Долгая индексация нового домена | Высокая | Нормально: 2–4 месяца до заметного трафика. Не паниковать и не переделывать структуру |
| Копирование контента конкурентами | Средняя | Быстрая индексация оригинала, оригинальные разборы вместо переписанных чужих |
| Претензии по авторским правам на задания | Низкая | Задания пишутся с нуля самостоятельно — риск минимален. Не копировать формулировки из платных сборников дословно |
| Выгорание на длинной дистанции | Средняя | Публиковаться маленькими порциями и сразу; видимый отклик из Метрики поддерживает мотивацию |

## 15. Правовые вопросы

Отказ от регистрации даёт крупное преимущество: **персональные данные не собираются и не обрабатываются**, поэтому требования 152-ФЗ (согласие, политика, уведомление Роскомнадзора, локализация баз) в основной части не применяются.

Всё же необходимо:
- Страница «О проекте» с контактом для связи
- Краткое уведомление об использовании Яндекс.Метрики и cookies
- Указание, что материалы носят информационный характер и не являются официальными материалами ФИПИ.
